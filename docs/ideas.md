# ideas.md: Potential features (unscheduled)
**Purpose**: a parking place for ideas as they come. Nothing here is planned, scheduled or promised.
**Rule (Adam, 2026-11-10)**: the roadmap does not grow until version 1.0.0-stable is reached; only then are other features considered. Only Adam moves an idea from this list into `docs/roadmap.md`.
Features that were decided against earlier are listed under "Dropped" in ARCHITECTURE.md section 2; they come back here only if Adam brings one back.

| Idea | Added | Notes |
|---|---|---|
| Vi / Vim key bindings (optional, switched on in settings) | 2026-11-10 | GtkSourceView 5 appears to provide a Vim input method (`GtkSourceVimIMContext`); to be confirmed against version 5.12 before any promise. |
| Emacs key bindings (optional) | 2026-11-10 | No ready-made support in GtkSourceView or GTK 4; it would be our own key handling, so a larger job than Vim keys. |
| Tab limit (optional): when more than N tabs are open (for example 20), the least recently used one closes, never one with unsaved changes, with a status bar message | 2026-11-10 | Planned for M2.6, dropped by Adam before M2.1: Vermilion does not close tabs on the user. It would need a recent-use counter in `DocumentList`. |
| Action chains (working name; also considered: Chord line, Quick verbs): a colon opens a one-line entry, then a string of letters runs actions in order when Enter is pressed. Example: `:wdb` + Enter would write the file, build, then debug | 2026-11-11 | Adam's idea. Each letter maps to a `GAction`, so the action table already exists. Open points for when it is considered: a colon is an ordinary character in a text editor, so it needs its own trigger (a shortcut, or Esc then colon) because Vermilion is not modal; a chain should stop at the first action that fails (a failed build must not start the debugger); the letter map fixed or user-defined; how it relates to Vim's `:` command line if Vim keys are ever added. Needs Build (M4) and Debug (M7) to be worth much. |
| Edit journal for crash recovery: instead of copying the whole document, append each edit (what was inserted or deleted, and where) to a small log in the background; recovery replays the log on the original file | 2026-11-11 | From the M2.2c talk (option E). Cost per keystroke does not depend on file size, so it suits huge files, but it is a new file format and replay must be exact. Considered only if the copy-based recovery of M2.2c (with its back-off and sliced copy) proves too slow on very large documents. |
| Native Anthropic Messages adapter | 2026-11-13 | Parked by Adam: the agent is local first (llama.cpp through the OpenAI-compatible API). Was gate M8.3. The provider interface of M6.1 is the seam; the adapter would need the same recorded-stream tests as the OpenAI-compatible one. |
| Native Gemini adapter (Gemini already works through Google's OpenAI-compatible endpoint) | 2026-11-13 | Parked by Adam. Was gate M8.4. Build only if the compatible endpoint lacks something needed. |
| MCP server (stdio): expose Vermilion's tool registry to other agents | 2026-11-13 | Parked by Adam. Was gate M8.7. The built-in agent calls its registry in process, so this only serves outside agents. The registry's shape (name, JSON schema, function) is the MCP shape, so it needs no redesign. |
| MCP client (stdio): let the agent call outside tool servers | 2026-11-13 | Parked by Adam. Was gate M8.8. Expansion, not a requirement for a working agent. |
| Key storage in the system keyring (libsecret) | 2026-11-13 | Parked by Adam (the keyring half of M6.6). Keys are `env:NAME` references until then; the key resolver answers `keyring:` with "not supported in this version", so adding it changes no format. Costs: a running keyring service (GNOME Keyring or KWallet; XFCE may have none), async calls, a fake for tests, a "store key" field in the setup dialog. Only matters for remote endpoints. |
| Context summarising: at about 80% of the context, older turns are summarised | 2026-11-13 | Parked by Adam (was gate M6.12). Until then the loop stops cleanly with "context full, use /clear" (M6.4). |
| Histogram diff (and patience diff) as an alternative to Myers | 2026-11-13 | Adam's idea. They anchor on lines that occur once and give nicer results on code with repeated lines such as `}`. The diff engine (M6.5) keeps the algorithm behind one function so it can be swapped. |
| Change sets, the heavy parts: persisted change sets (revert after a restart), per-hunk Accept and Revert in the DiffView, one undo step per agent turn | 2026-11-13 | Parked by Adam; M6.6 is the lean version (in-memory change sets, snapshots, whole-turn revert). Per-hunk revert needs patch application against a file the user may have edited since; grouped undo needs GtkSourceView's user-action grouping held open across an asynchronous turn while the user may also type. |
| `.rpm` packages, built and tested in a Fedora virtual machine | 2026-11-13 | Parked by Adam. The `.deb` packages and the release zip with `install.sh` cover M9. Open points were the dependency names and the Fedora release. |
