## 1. What this is  *(Decided)*
Vermilion Editor is a native Linux text and code editor written in C++17 on GTK 4 and GtkSourceView 5, with a built-in AI agent, a project build system integration, a debugger and a terminal. It is released under GPL-3.0-or-later. Target system: Ubuntu 24.04 (GTK 4.14, GLib 2.80, gdb 15.1). Linux only. It ships as three programs: the light editor `vermilion`, the IDE `vermilion-ide` and the model monitor `ctxmon` (7.12).

## 5. Conventions  *(Decided 2026-11-05 as part of the language decision; details Proposed)*
- **Errors:** no C++ exceptions in project code. An exception escaping through a GTK callback is undefined behaviour. Use `std::optional` or a small `Result<T>` type; at the GTK boundary use `GError`. Compile with `-fno-exceptions` where the dependencies allow it.
- **Memory:** RAII only. Smart pointers or the `gtkx` helpers for GObject references; no raw `new`/`delete`/`g_free` outside the helpers.
- **Threading:** the GLib main loop plus async I/O (`GSubprocess`, libsoup async API, `GTask`) for network, builds, debugger and monitors. Threads only for heavy computation (large diffs). Widgets are touched from the main thread only. The main loop is never blocked.
- **Paths and data:** `std::filesystem` or GIO. XDG locations for config, data, cache and state. Text is UTF-8; encoding and line endings are explicit at file boundaries.
- **Style:** `clang-format` (`.clang-format` committed at M0.2: LLVM base, indent 4, 100 columns; enforced by ctest `Format.Check`), warnings as errors (`-Wall -Wextra -Werror`), `clang-tidy` where cheap, ASan and UBSan builds run by Adam on request.
- **Size and shape:** one responsibility per file; a source file over 300 lines is reviewed, over 500 is split (tests and data tables 500 and 800); functions over 50 lines are flagged; UI is one widget or panel class per file pair and `window` only assembles panels. Details: AGENTS.md rule 16.
- **Regular expressions:** GLib's `GRegex` (PCRE2: lookbehind, named groups, no exceptions), part of GLib and allowed in every layer; `std::regex` is not used (Adam, 2026-11-07). Later users: ctxmon parsing (M1), editor search (M2.3), problem matchers (M4.4).
- **Identity stability:** never rename config keys, JSON fields, file formats, command names or IDs when only display text changes.

## 7. Feature designs

### 7.1 Editor  *(Decided scope, Proposed detail)*
Tabs (`GtkNotebook`), open and save, encodings through GLib converters (UTF-8 default), line endings detected and preserved (LF for new files), search and replace with `GRegex`, go to line, line numbers, GtkSourceView language detection and style schemes (follows the system dark mode). Gutter marks for breakpoints and the current debug line. File monitoring (see 7.6 "External changes"). Large-file behaviour was measured in the M2.0a spike (GTK 4.14.5, GtkSourceView 5.12.0, async `GtkSourceFileLoader`; the window stays usable while a file loads): a 50 MB file of 0.78 to 1.0 million lines loads in 4 to 6 seconds with a peak of 0.5 to 0.7 GB when no language is set, but in 72 seconds (highlighting off) to 87 seconds (on) with a peak of 1.1 to 1.6 GB when the C++ language is set; a 2 MB file on one line takes 40 seconds and 5 GB and hangs the view. Setting the language only after the load has finished removes the slow load (the same C++ file: 4.4 seconds, the language set in 7 ms, colouring then fills in while the window stays usable, peak 1.1 GB), so the editor loads without a language and sets it afterwards. Word wrap on the 50 MB text file loads in 4.2 seconds but lags while it lays out and peaks at 6.8 GB. Select All and deleting the whole text stayed responsive in every run. Decided for M2.2 (Adam, 2026-11-11): a file whose longest line is above a limit (measured at M2.2, about 200,000 characters expected) or that contains zero bytes asks "Open anyway / Cancel" before loading; word wrap is always off when a file opens and is switched on per document. Encodings are tried in a fixed order (UTF-8 with or without BOM, UTF-16 with its BOM, Windows-1252, Latin-1) and a result other than UTF-8 is always shown; the Encoding button separates "Reopen as…" (re-read) from "Save as…" (convert). Saving writes a new copy beside the file, flushes it and swaps it in, so the original survives any failure. Crash recovery (M2.2c, decided 2026-11-11) keeps a private recovery copy of every edited document in the XDG state folder (5 s after typing stops, at the latest 30 s after the first unsaved change; large documents back off) and offers each one at the next start: Recover, Discard or Decide Later. Window furniture, document tabs, start state, status bar and shortcuts: 7.10.

**Open and save as built (M2.2, 2026-11-11).** The core `TextScanner` (`src/core/text_scan.*`) reads a file once, in 64 KiB blocks on the main loop, before it loads, and decides the format itself, because `GtkSourceFileLoader` checks the encoding only on the first block, takes the line ending from the first line and ignores a byte-order mark: a strict whole-file UTF-8 check, a UTF-8 or UTF-16 mark, otherwise Windows-1252 (or Latin-1 when one of its five undefined bytes occurs), the line ending most lines use (a file with several kinds shows Mixed), the longest line (above 350,000 characters the user is asked) and NUL bytes (binary). The loader then gets exactly one candidate encoding and no language; a binary file opened anyway, or one whose bytes had to be escaped, is read-only. The byte-order mark stays in the buffer as U+FEFF. Saving uses `GtkSourceFileSaver` (the chosen encoding, one newline type on every line, a new copy beside the original that is swapped in); the implicit trailing newline is off so a file round-trips byte for byte; "changed on disk" is the saver's `EXTERNALLY_MODIFIED` error and asks Save Anyway / Cancel. Asynchronous GIO callbacks go through `gtkx::AsyncGuard`, which tells a callback whether the object that started it still exists. Measured: a 38.9 MB file saves in 6.5 s with the window usable.

### 7.2 Directory sidebar  *(Decided)*
Right-hand side, first tab of the right stack. Behaviour is specified in `docs/requirements/directory-sidebar.md`. GTK 4 mapping: `GtkTreeListModel`, `GtkTreeExpander`, `GtkListView`, `GFileEnumerator` (async), `GFileMonitor`. Filesystem work sits in core behind a small interface with a fake for tests.

### 7.3 Build  *(Decided scope, Proposed detail)*
Per-folder configuration in `.vermilion/project.json`: build command, run command, working directory, environment. Presets detect CMake, Make, Ninja, Cargo, Gradle and Bazel from the files in the folder. Output goes to the Output pane; error lines from gcc, clang, rustc and javac are parsed by problem matchers (regular expressions, user-extendable in JSON) into the Problems list and clickable `file:line:column` links. Commands run on `GSubprocess`; the agent can call the same entry point.

### 7.4 Terminal  *(Decided)*
VTE terminal tabs in the bottom panel, shell from `$SHELL`, started in the opened folder. Run and Debug use a terminal tab so the program has a real stdin and stdout. The ctxmon panel offers the same terminal.

### 7.5 Debugger  *(Decided)*
Debug Adapter Protocol over stdio (Content-Length framed JSON, parsed with json-glib). First adapter: gdb's built-in DAP (`gdb --interpreter=dap`, gdb 15.1 on the target), for C, C++ and Rust. A short spike confirms breakpoints, stepping, stack, scopes, variables and evaluate work reliably; if not, fall back to GDB/MI. Other adapters (`lldb-dap` and so on) can follow with the same client. UI: click the gutter to set a breakpoint; continue, step over, step into, step out; stack, locals and watch expressions; current-line marker. Not in the first version: attach, core dumps, remote debugging.

### 7.6 Agent  *(Decided; names Proposed)*
**Providers.** One agent loop, provider adapters behind an interface:
- OpenAI-compatible (Chat Completions with tool calls, streaming): covers OpenAI, local llama.cpp and other compatible servers, and Gemini through Google's OpenAI-compatible endpoint.
- Native Anthropic Messages adapter.
- Native Gemini adapter later, only if the compatible endpoint lacks something needed.
Provider APIs change; each adapter is verified against current documentation when it is planned. Streaming uses server-sent events; a Cancel control stops the request and the running tool.

**Setup dialog.** Opened the first time the Agent tab is used: provider, base URL, API key (stored in the system keyring, environment variable as fallback; JSON only ever holds a reference such as `keyring:name` or `env:NAME`, and a plaintext key is rejected), model, a connection test, the permission preset and the context budget. If a llama.cpp server answers on `127.0.0.1:8080`, the model and context size are read from `/props` and the monitor (7.7) is offered.

**Tools** (one registry, also exposed over MCP): `read_file` (line ranges), `replace_text` (exact match), `create_file`, `list_dir`, `search`, `open_file`, `run_build`, `run_command`. Tool results are truncated with an explicit marker.

**Context.** Each request carries the system prompt, the project file (7.8) and a small editor-state block (open tabs, active file, selection, folder root); everything else comes through tools. Per-endpoint context budget; at about 80% older turns are summarised. Per-task limits: 50 turns and a token cap by default.

**Permission presets.** Rules are JSON, a glob per tool, the last matching rule wins:
| Preset | Edits | Shell | Network |
|---|---|---|---|
| Restricted (default) | ask each time | ask each time | model endpoints only |
| Balanced | free inside the folder | free, with a deny list: commit, push, destructive git, writes or deletes outside the folder, other network | model endpoints only |
| Unrestricted | free | free | free |
| Custom | user JSON | user JSON | user JSON |
Switching to Unrestricted needs a confirmation dialog and shows a persistent red badge. **Hard guards in every preset:** the agent cannot change its own preset and cannot read API keys. Approvals in Restricted mode are inline Approve and Deny buttons with "allow for this session". A default "never send to remote endpoints" list (`.env`, `*.pem`, `id_*`, `*secret*`) is enforced in the file tools. The status bar shows the active endpoint and whether it is local (loopback) or remote; an append-only request log in the XDG state directory records endpoint, time, sizes and tool calls (prompt text off by default).

**Chat.** `/clear` saves the transcript to the archive and starts empty. Archives are JSON plus an exported Markdown copy under the XDG data directory, per folder; `/history` lists and opens them read-only. Every message, code block and generated prompt has a **Copy** button; `/copy` copies the last output.

**Slash commands and the gate framework.** Commands are Markdown templates in `.vermilion/commands/` (user-editable) with built-in defaults. `/gate <task>` fills the standard gate prompt (opening block, CONTEXT, STRICT RAILS, STEPS, EVIDENCE) from the project file and live facts such as `git status` and the modified-file list, and shows it as a card with one Copy prompt button. `/audit` takes a pasted agent report, runs the checks with the tools and issues a verdict (PASS, PASS WITH NOTES, FAIL) and the next prompt. Scheduled after the agent core (v0.4).

**Review of agent changes: side-by-side diff.** The core diff engine returns aligned rows (left, right, kind, word-level highlights). The `DiffView` widget is two read-only source views with filler lines and a shared scroll adjustment, folding of unchanged regions and Accept or Revert buttons per hunk in the centre. It serves proposed edits in Restricted mode, after-the-fact review in the other presets, the "show diff" button on external changes, and audits. Each agent turn is a change set; files changed on disk that are not open are snapshotted into the XDG cache first so revert never depends on git. One undo step per agent turn per document; edits carry the buffer version the agent read and fail if the buffer changed meanwhile.

**External changes.** `GFileMonitor` on open files and expanded folders (not the whole tree), debounced; our own saves are ignored by comparing modification times. A clean buffer changed on disk reloads automatically as one undo step; a dirty buffer shows a banner: Reload, Keep mine, Show diff. Agent edits to an open file go through the buffer; edits to closed files go to disk after a snapshot.

**Cost.** The user defines input and output price per million tokens for each endpoint, including a local model, to see what the same work would cost on a paid model. No prices are shipped. Token counts come from the `usage` fields of each response (streaming requires usage on the final chunk, confirmed per provider). Totals per conversation and per session sit beside the context bar.

**MCP.** Vermilion is an MCP server over stdio exposing the same tool registry, and an MCP client for stdio tool servers. HTTP transports and ACP are deferred.

**Chat UI details (Adam, 2026-11-10):** while the agent works, its status reads "Processing" (no playful or rotating words); the model's reasoning text is collapsed by default and expands to the full text, never cut short.

**Manual (Adam, 2026-11-11), built in M2.2b:** `docs/manual/` is the user manual, one short Markdown file per topic, listed in `docs/manual/index.md`. CMake collects every `*.md` there at configure time into a second GResource (`vermilion_manual`, prefix `/io/github/adamjeremy_sk/Vermilion/manual`), so a docs sweep adds a topic with no code change. Help → Index (`F1`) opens a separate read-only `HelpWindow` on `index.md`, one page at a time, with Back and Index buttons (`Alt+Left`); a second Help → Index brings the open window forward. In core, `parse_manual` and `parse_spans` turn a page into blocks and spans for a Markdown subset (headings, paragraphs with their wrapped source lines joined, `- ` lists, bold, inline code, tables, and links to other topics, `name.md`); anything else is shown as plain text and counted as a fallback, never dropped, and `PageHistory` is the bounded list behind Back. The window is a column of `GtkLabel`s (text escaped for Pango markup) and `GtkGrid` tables in a scrolling area; the labels are not selectable yet. Display-free tests keep every manual file inside the subset, linked from the index and identical to its compiled copy. A man page is generated from this Markdown only when 1.0.0-beta is packaged (Adam, 2026-11-11).

### 7.7 ctxmon (model monitor)  *(Decided)*
From 2026-11-07 Vermilion's ctxmon is the source of truth and all ctxmon development happens in this repository (Adam). The Python original `reference/ctxmon/ctxmon_gtk.py` (Adam's own code, GPL-3; copied from `~/Projects/llm-suite-test` on 2026-11-05, sha256 `895a34f7...d407`, with its logo `ctxmon.svg`) is frozen: it is never built or linked, it is not re-copied, and it serves only as the oracle for the M1 tests and as the behavioural reference for the M5 cards. Gate M5.6 removes all Python from the repository (Adam, 2026-11-07): the expected values become inline C++ tables in the tests, the original and `tools/ctxmon_oracle.py` are deleted, and `SourceCheck.Repo` rejects any `.py` file from then on.

**Layout.** `src/ctxmon/core` holds the logic (no GTK), `src/ctxmon/ui` the cards and the standalone executable, `tests/ctxmon` the tests; core and UI never mix (section 4).

**Logic (M1).** Log token lines (`n_tokens`, `n_past`, session floor), timing lines and finished-request history, `/slots` and `/props` parsing, live speed over a two-second window, server state with history pruning, warnings at 80% and 95% (no time-until-full estimate: dropped at M1.7 because it jumped with the speed figure, Adam 2026-11-08), graph geometry, `fmt_duration`, VRAM from AMD sysfs or `nvidia-smi` output. Everything is a pure function on text, JSON strings or a directory tree, tested against expected values produced by the Python original (oracle script and fixtures, M1.0). Hardened at M1.7 against hostile input: a server response over 1 MiB or nested deeper than 32 levels is not parsed (own depth scan before json-glib, which in version 1.8 crashes on very deep nesting), negative counts from `/slots` count as missing, and GPU files are read only if they are ordinary files of at most 64 bytes. The Python's thread-based poller and blocking HTTP are not ported; the I/O is redesigned in M5 on GIO and libsoup async calls on the main loop.

**UI (M5).** A card per server (several servers supported), with graphs and the terminal, in two forms built from one shared widget set: the **ctxmon** tab in the right-hand stack (added at M5.5, once the right-hand stack exists), and a **standalone executable** (`ctxmon`, own `GtkApplication` window, no editor or folder needed; application ID `io.github.adamjeremy_sk.Ctxmon`; decided 2026-11-11, 7.12). Dropped from the original: the tray icon (GTK 4 has none) and `notify-send` (replaced by `GNotification`). llama.cpp servers only.

### 7.8 Project file  *(Decided)*
Two files in the opened folder: `PROJECT.md` (human and agent readable: purpose, directory layout, conventions, decisions, current state, next steps, in the shape of this document) and `.vermilion/project.json` (build, run and debug configurations, permission overrides, agent settings, gate templates in use) *(names proposed)*. The agent proposes updates to `PROJECT.md` after changes as an ordinary change set.

### 7.10 Window, look and the light program  *(Decided 2026-11-10, Adam; the feather mode of that date became the light program on 2026-11-11, see 7.12)*
**Look.** One fixed classic Windows 2000 style, made by a single GTK CSS stylesheet (a resource) loaded at application priority over the desktop's own GTK theme (the M2.0b spike tried both the desktop theme and GTK's built-in Default underneath; Adam chose the desktop base, which looked best; Vermilion never changes the theme name). No custom drawing code and no replacement widgets. Restyled: buttons, entries, notebook tabs, the menu bar, status bar panels, panel borders, paned dividers and selection colours. Left as GTK draws them: scrollbars, dialogs and the file chooser; the one dialog rule is that selected text in Help → About has no highlight, because GTK gives the focus to the program name when About opens, which selects it (Adam, 2026-11-11). Popup menus keep the desktop theme except their text colours (black, grey when disabled), the navy highlight with white text, and a gap before the shortcut (Adam, 2026-11-11). The structure (bevels as stacked inset shadows, tight spacing, no transitions, no rounded corners) is shared; the colours come from two palettes. **Light**: chassis `#CECECE`, white highlight edges, `#808080` and near-black shadow edges, white text areas, navy selection. **Dark**: the same structure on a dark grey chassis with a lighter highlight edge and a darker shadow edge. Colour mode is a setting: Light, Dark or Follow system. GtkSourceView uses its `classic` scheme in light mode and a dark scheme in dark mode. Follow system (measured in the M2.0b spike on XFCE with Greybird, GTK 4.14.5) reads, in order: the settings portal's `org.freedesktop.appearance` `color-scheme` (absent on Adam's XFCE: its portal has no Settings interface), a theme name ending in `-dark` (what XFCE changes; the spike followed Greybird-dark and back live through `notify::gtk-theme-name`), then `gtk-application-prefer-dark-theme` (never set by XFCE). In dark mode Vermilion sets prefer-dark for its own process so the native parts follow. A GtkSettings value is set or reset only when Vermilion's wanted state changes: touching it otherwise makes GTK announce the setting again, which looped in the spike. The full bevelled stylesheet worked, so the lighter-touch fallback is not needed. GtkSourceView 5.12 ships `classic` and `classic-dark`. Greybird's own GTK 4 stylesheet still prints about 50 parser warnings at every theme load; they come from the desktop theme, not from Vermilion. This is one fixed look with two palettes, not the dropped theme system. **Classic details (Adam, 2026-11-10, after a review of the M2.0b screenshot):** (1) the selected notebook tab is fused into its page: taller than the others, no border under it, the unselected tabs sit lower and darker (Win2000 tab control), in our palette, not the `#D4D0C8` family; if GTK 4's CSS rejects the negative margin that overlap would need, the fusion is made with matching colours and no border instead; (2) the editor sits in a sunken two-pixel well like the entries; styling the line-number gutter needs the GtkSourceView style scheme, not CSS, so it is decided after the well is seen; (3) the per-tab close button shows a bold `×` (text, not an icon) in a small raised bevelled square of about 16 px; (4) menu mnemonics stay hidden until Alt is pressed (Windows 2000's own default); no Pango underline markup in menu labels, which would not match the real access keys.
**Fonts, title bar, icons.** The system font for the interface (nothing bundled; W95FA was considered and declined), GTK's default title bar (no custom title bar), and no icons or artwork: the few buttons (status bar panels, dialog buttons) are text. The application icon is the one exception (Adam, 2026-11-11): `res/vedt/vermilion-icon.svg` (renamed from `Vermilion Editor Icon.svg`) above the name in Help → About and as the desktop icon; `res/vedt/vedticon.svg` as the small title-bar icon. The SVGs are the masters; every build renders them to PNG with `rsvg-convert` (Adam, 2026-11-11: a build tool is acceptable, the program itself gains no dependency, and GTK 4 reads PNG with its own loader), the small icon at 16 and 24 px and the large one at 32, 48, 64, 128 and 256 px, all under the application ID, so GTK picks the small icon for the title bar and the large one for the panel, Alt+Tab and About (revisited if it does not look right in use). The PNGs are written into the build folder, compiled into the resources under `icons/<n>x<n>/apps/` (the GTK 4 layout for icons in resources, without a theme folder) and found through the icon theme, because GtkApplication adds `<resource base path>/icons` to it (gate M2.1c); the window default icon and the About logo use the application ID as icon name. Whether the title bar shows the icon depends on the window manager theme (Greybird on XFCE shows a window-menu arrow there); nothing generated is committed; installing them for the desktop belongs to packaging (M9) and the desktop entries (M2.6b). The editor font is the system monospace by default and a setting.
**Commands.** Every command is a `GAction`. Menu items, shortcuts and the few buttons point at the same action, so enabling and disabling (no document open: Save and Find greyed out) happens in one place. A menu or button is added only at the milestone that builds its feature; there are no dead items.
**Menu bar** (`GtkPopoverMenuBar`, underlined access keys): **File** (New File, Open File, Open Folder, Recent Folders, Save, Save As, Save All, Reopen with Encoding, Reload from Disk, Close Tab, Close Folder, Quit; New Project and Adopt as Project at M8); **Edit** (Undo, Redo, Cut, Copy, Paste, Select All, Line Endings); **Search** (Find, Find Next, Find Previous, Replace, Go to Line); **View** (Next Tab, Previous Tab, Line Numbers, Word Wrap, Zoom In, Zoom Out, Reset Zoom, Colour Mode; later Show Files, Agent, ctxmon, Bottom Panel, Output, Problems, Terminal, Debug); **Build** (M4: Build, Run, Stop, Next and Previous Problem, Build Settings); **Debug** (M7: Start Debugging, Continue, Step Over, Step Into, Step Out, Stop, Toggle Breakpoint, Remove All Breakpoints, Add Watch); **Agent** (M6: New Chat, Chat History, Permission Preset, Cancel Request, Agent Setup); **Tools** (Settings from M2.5; Project Settings, Open PROJECT.md, Open ctxmon Window later); **Help** (Index from M2.2b: the manual by topic, which replaces a separate Keyboard Shortcuts item; About). Open Folder, Recent Folders and Close Folder arrive with the sidebar at M3.0.
**No toolbar** (Adam, 2026-11-10, after seeing it in the M2.0b spike): the window is keyboard first and lean. Every command is a menu item that shows its shortcut, including Build, Run and Stop (M4) and the debugger's run control (M7); there is no button strip, not even during a debug session.
**Status bar** at the bottom of the window, as in gedit: a wide message panel on the left, then right-aligned recessed panels: Language, Tab Width, Encoding, Line Ending (each a flat button that opens a short list), Line and Column, INS or OVR. Later: the agent endpoint with its local or remote marker, the red Unrestricted badge, build status.
**Document tabs.** Fixed width, 18 characters of the system font (never resized to fit), long names cut with an ellipsis, the full path as tooltip, a close button at the tab's right edge (the name takes the remaining width; Adam, M2.0b), a marker for unsaved changes, middle-click closes, drag to reorder. When tabs overflow the strip, the notebook's arrow buttons and the mouse wheel move through them and the active tab scrolls into view (no scrollbar: that would need a custom tab strip). **No tab limit** (Adam, 2026-11-10, before M2.1): Vermilion never closes a tab on its own; an automatic limit is parked in `docs/ideas.md`. **Tab Width** (indent size, in the status bar) is per document, starting from the settings value.
**Start state and closing.** Default: a new untitled document. Settings can change it to reopen the last document (a single file, a small exception to the dropped session restore) or a blank window. Closing an untitled, unedited document needs no prompt; an edited one asks Save / Close Without Saving / Cancel (M2.2; for an untitled document Save asks for a name first, and cancelling that cancels the close); quitting asks about each edited document in turn, selecting its tab, and Cancel stops the quit. When the last document closes, `vermilion` quits and `vermilion-ide` shows a blank window in which every document command (Close Tab, Save, Save As, the Edit items, Next and Previous Tab; Find once it exists) is greyed out. When the active tab closes, its neighbour to the left becomes active (the one to the right if it was first); closing a background tab, including with its close button, leaves the active tab as it is (Adam, 2026-11-10, after trying M2.1 STEP 4). Tabs keep their fixed width whatever their number; they are never stretched to fill the strip. Untitled documents take the lowest free number.
**Shortcuts** (fixed for now): `Ctrl+N` New, `Ctrl+O` Open, `Ctrl+S` Save, `Ctrl+Shift+S` Save As, `Ctrl+W` Close Tab, `Ctrl+Q` Quit; `Ctrl+Z` Undo, `Ctrl+Y` and `Ctrl+Shift+Z` Redo, `Ctrl+X`, `Ctrl+C`, `Ctrl+V`, `Ctrl+A`; `Ctrl+F` Find, `F3` and `Shift+F3` Next and Previous, `Ctrl+H` Replace, `Ctrl+G` Go to Line; `Ctrl+PageDown` and `Ctrl+PageUp` next and previous tab, `Ctrl+=`, `Ctrl+-`, `Ctrl+0` zoom, `F1` Help → Index (and `Alt+Left` for Back inside the help window). At the Build and Debug gates, Visual Studio keys: `F7` Build, `F5` Run or Continue, `F9` Toggle Breakpoint, `F10` Step Over, `F11` Step Into, `Shift+F11` Step Out.
**Settings window.** Classic and transactional: changes are held until `OK` (save and close), `Cancel` (discard) or `Apply` (save and stay open; disabled until something changes).
**The light program.** The `--feather` mode decided on 2026-11-10 became its own program, `vermilion`, on 2026-11-11 (7.12): a plain text editor and a replacement for gedit or Mousepad, with files from the command line and from "Open with", a desktop entry for text files, no folder, project, build, agent or terminal, and the menus File, Edit, Search, View and Help only. ### 7.11 Crash recovery  *(Decided 2026-11-11, Adam; the file format approved the same night)*
A basic editor function, not a feature: a killed or crashed editor offers the unsaved text at the next start.
**Where.** `$XDG_STATE_HOME/vermilion/recovery/<program>/`, with `light` (`vermilion`) and `ide` (`vermilion-ide`) as the program folders, so each program looks only at its own (one running instance per application ID). The folder is created with mode 0700 and every file with 0600. The agent's file tools are barred from it (hard guard, M6). Copies are never aged out automatically: start-up asks until the user decides.
**When.** Only documents with unsaved edits (untitled ones included; none for read-only or still-loading ones). A copy is written 5 s after typing stops and at the latest 30 s after the first unsaved change since the last copy; one document at a time; the write runs on GIO's thread pool, but the text must be taken from the buffer on the main loop. A copy is deleted on save and on Close Without Saving. A failed write shows one status message and then stays quiet. Large documents: each copy times its own main-loop freeze and the next waits at least 20 times that; above a ceiling size there is no copy and the status bar says "Too large for recovery copies" (the ceiling is counted in characters, the constant `kRecoveryCeilingChars` in `src/core/recovery_schedule.h`, provisional at 100,000,000 and fixed from the log in the last step); if the freeze on a 39 MB buffer proves over about 100 ms the text is taken in 1 MB slices on idle callbacks, restarted if the buffer changes meanwhile. Nothing is measured outside the repo (Adam, 2026-11-11): the wiring logs every copy's hold, the first version takes the text in one call, and slicing is a small gated follow-up only if Adam's run on the 39 MB file shows it is needed. The ceiling is the size where the measured freeze would pass about 1 s (every copy logs its freeze under `G_MESSAGES_DEBUG=vermilion`). An edit journal instead of copies is parked in `docs/ideas.md`.
**Start-up.** One question per copy, in turn, selecting nothing else: Recover, Discard or Decide Later (keeps the copy, asked again at the next start), "n of m" in the text and Recover All when two or more wait; it shows the time of the copy and the file's modified time now. A recovered document opens modified, with its original path (untitled if it had none); if the file's time differs from `file-mtime`, the text says it changed on disk since the copy's text was based on it, and the first save asks the Save Anyway question. No blank start document is made when a copy is recovered. A damaged copy offers only Discard or Decide Later. No Compare button until the diff view (M6.9).
**The recovery file** (`<random id>.vrec`; the id is a UUID made once per document, so a new copy replaces the old one; the name leaks no path). A header of `key: value` lines, a blank line, then exactly `length` bytes of body:
```
VERMILION-RECOVERY 1
uri: file:///home/adam/Projects/demo/main.cpp
copied: 1794452733554000
file-mtime: 1794450001123456
encoding: utf-8
line-ending: lf
length: 18342

<exactly 18342 bytes of text>
```
The body is the buffer text exactly as GTK holds it, always UTF-8 and never converted to the document's encoding (a character typed into a Latin-1 document may not exist in Latin-1); the header records how the document was stored, with the stable ids of `text_format.h` (`utf-8`, `utf-8-bom`, `utf-16le`, `utf-16be`, `windows-1252`, `latin-1`; `lf`, `crlf`, `cr`). Keys: `uri` (percent-encoded `file:///` URI; untitled documents have `title` instead, e.g. `Untitled 3`; exactly one of the two), `copied` and `file-mtime` (Unix time in microseconds, UTC; `file-mtime` is the file's time when the document was loaded or last saved, absent for untitled documents), `encoding`, `line-ending` (the ending the next save writes), `mixed: yes` (only present when the text has mixed line endings), `length`. Required: `copied`, `encoding`, `line-ending`, `length`. Keys are lowercase letters and `-`; a line without `: `, a repeated key, a bad number, an unknown id, a `\r` or NUL in the header, a header over 32 KiB, a line over 16 KiB, a different version number, or a file whose size is not header plus `length` makes the copy damaged. Unknown keys are ignored (a later version may add fields). Not saved: caret and scroll. Code: `src/core/recovery_file.*` (format, no GTK), then the schedule, the store, the wiring and the start-up question (roadmap M2.2c). **The store** (`src/core/recovery_store.*`, M2.2c STEP 3; Orchestrator, 2026-11-12): a copy is written to a temporary file in the same folder (`.vrec-tmp-XXXXXX`, made with mode 0600 by `g_mkstemp_full`), flushed with `fsync` and renamed over `<id>.vrec`, with GLib and POSIX calls only (no GIO), so a failed or interrupted write leaves the old copy whole and no half copy under a real name; `g_file_replace` is not used because for a file that does not exist yet it writes the destination itself and in place (found by a test against GLib 2.80). Reading never follows a link or waits on a pipe, refuses anything that is not a regular file or is over 1 GiB (`kRecoveryMaxFileBytes`) before reading, and a header check reads only the first 32 KiB. Start-up removes only leftover `.vrec-tmp-*` files in its own folder and ignores anything else.

### 7.12 Three programs  *(Decided 2026-11-11, Adam; replaces the feather mode of 2026-11-10)*
Adam wants a light program for note editing, split off from the IDE, which will grow large. Vermilion therefore ships as three programs, and the light editor is the first one Adam uses every day (DOGFOOD 1 at M2.6b: it replaces gedit and Mousepad on his system):
| Command | Application ID | What it is | Appears |
|---|---|---|---|
| `vermilion` | `io.github.adamjeremy_sk.Vermilion` | The light editor, a replacement for gedit or Mousepad: files from the command line and from "Open with", a desktop entry for text files, the menus File, Edit, Search, View and Help, no folder, project, build, agent or terminal; quits when the last document closes. | M2.6b |
| `vermilion-ide` | `io.github.adamjeremy_sk.VermilionIde` | The whole IDE: everything in `vermilion` plus the opened folder and directory sidebar, build, Output and Problems, the terminal, the agent, the debugger and the ctxmon tab. | executable from M3.0 *(timing decided 2026-11-11)* |
| `ctxmon` | `io.github.adamjeremy_sk.Ctxmon` | The standalone model monitor (named `vermilion-ctxmon` before 2026-11-11). | M5.4 |
**Feature rule.** A feature that needs a folder, a project, a build, the agent or a terminal is IDE-only; anything else goes in the shared base, and both editors get it. Everything milestone M2 builds is in the base, so a change to editing reaches both programs.
**One base, thin programs** (Adam chose this shape, 2026-11-11). At M2.6b the editor code in `src/ui` becomes a static library (name and directories proposed), and each program is a thin `main` plus what only it needs. The light program stays light by what it links: no VTE, libsoup, libsecret, `vermilion_agent` or ctxmon code. A ctest checks the link libraries of the `vermilion` executable (M2.6b). The stylesheet, the icons, `gtkx` and `vermilion_core` sit under all three; ctxmon also needs libsoup and VTE but not GtkSourceView. The configure step may keep asking for every package (Adam builds everything); what counts is what each executable links.
**Settings** *(decided 2026-11-11)*. One `settings.ini` is read by both editors; each loads it, changes the keys it knows and writes it back, keeping the keys it does not know (M2.5). Recovery copies are per program (`light`, `ide`; 7.11); ctxmon keeps none.
**Names and rail 9** *(decided 2026-11-11)*. The command `vermilion` changes meaning (it was to be the whole editor, then the editor with a `--feather` flag) and the standalone monitor is `ctxmon`, not `vermilion-ctxmon`. This is a deliberate exception to the identity rail (AI_ONBOARDING.md 3.9), allowed because nothing is released; after the first release the rail has no exceptions. The flag `--feather` and the ID `io.github.adamjeremy_sk.Vermilion.Feather` were never built.
**Icons** *(decided 2026-11-11)*. `vermilion` and `vermilion-ide` use the same icons as today (`vermilion-icon.svg`, the page, and `vedticon.svg`, the small badge), which the build renders under each program's own application ID (so the two editors look alike in a taskbar; Adam accepted that). `ctxmon` uses Adam's prepared icon `reference/ctxmon/ctxmon.svg`; whether the file stays in `reference/` or moves to `res/vedt/` when gate M5.6 removes the Python from that folder is decided at M5.4.
**Packages** (Adam: shape 2026-11-11, formats 2026-11-12). Three packages: `vermilion`, `vermilion-ide` and `ctxmon`, each built as a `.deb` and as an `.rpm`. `vermilion-ide` Depends on (`.rpm`: Requires) `vermilion` and `ctxmon` (same version), so installing the IDE brings the light editor and the monitor; `vermilion` and `ctxmon` only Suggest each other and `vermilion-ide`, so the light editor installs with GTK 4 and GtkSourceView 5 alone. The base is a static library, so there is no fourth library package. **Release formats (Adam, 2026-11-12): the `.deb` and `.rpm` packages plus a release zip that holds the prebuilt binaries and a custom `install.sh`. No AppImage (declined) and no Flatpak** (its sandbox blocks the host compiler, debugger and the agent's shell). **The zip (Adam, 2026-11-12):** one zip holds all three programs; `install.sh` installs and uninstalls, and lets the user choose which programs to install: the light editor, the IDE, ctxmon, or all three; it also checks that the system's GTK 4, GtkSourceView 5 and glibc are new enough for a binary built on Ubuntu 24.04 and names the missing package. The `.rpm` is built and tested in a Fedora virtual machine (Adam has Bazzite in a dual boot but would use a VM). Still open for M9: the install prefix (system-wide or in the home folder), whether choosing the IDE in `install.sh` also installs the other two (the packages do, 7.12), and the `.rpm` dependency names and the Fedora release.
