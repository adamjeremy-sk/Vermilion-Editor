- 2026-11-12 — (Orchestrator, within the M2.2c design) **The recovery store does not use GIO.** Writing the store tests against the real GLib 2.80 showed that `g_file_replace` (`G_FILE_CREATE_PRIVATE | G_FILE_CREATE_REPLACE_DESTINATION`) uses a temporary file only when the destination already exists; for a new id it writes the destination itself and in place, so a failed write left a partial `.vrec` under a real name. The store therefore writes a temporary file in the same folder (`g_mkstemp_full`, 0600), flushes it with `fsync` and renames it (`g_rename`); no GIO, no new dependency, and ARCHITECTURE.md 7.11 now says so (leftovers are `.vrec-tmp-*`, not `.goutputstream-*`).
